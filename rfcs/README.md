RFCs 0005 to 0007 define Ironstone methods that NeoLibrary is built with. They are summarized for clients on [Ironstone Methods](https://www.ironstoneadvisory.com/what-we-do/ironstone-methods); these RFCs are the full definitions.

## How RFCs work here

- **Numbered, never renumbered.** RFC-0001 stays RFC-0001 forever.
- **Versioned.** A change in meaning gets a new version (1.0, 1.1, 2.0) and a line in the RFC's change log. Typos don't.
- **Statuses:** Draft, Accepted, Superseded. A superseded RFC stays in the repo and names its replacement.
- **One idea per RFC.** If a document needs two titles, it's two RFCs.
- **Prose first.** Each RFC explains the idea in plain language before any code or schema.

To propose one, copy the header block from any RFC, take the next number, and open a pull request with the status set to Draft.
